## stk Deploy Script

ZigLag uses the production deploy script maintained by stk. The script targets a fresh Ubuntu server and installs PostgreSQL, Redis, Caddy, Python, uv, systemd services, database migrations, and automatic TLS.

```bash
wget -qO /tmp/deploy.sh https://raw.githubusercontent.com/level09/stk/master/deploy.sh
sudo DOMAIN=invoices.example.com REPO=level09/ziglag DB=postgres bash /tmp/deploy.sh
```

Run the command on the target server as root. Set `DOMAIN` to the final hostname before installation. Set `REPO` to the GitHub owner and repository. The production example selects PostgreSQL explicitly.

The script prints generated credentials at the end and stores a copy on the server. Move the credentials to your password manager after installation.

## Required Production State

- PostgreSQL stores application data.
- Redis stores server-side sessions.
- Caddy terminates TLS and proxies WebSockets.
- systemd runs uvicorn and restarts it after failure or reboot.
- `QUART_DEBUG` is disabled.
- `SECRET_KEY`, `SECURITY_PASSWORD_SALT`, and `SECURITY_TOTP_SECRETS` contain independent random values.

## Invoice Archive

ZigLag stores the exact PDF created when an invoice is issued under `instance/invoices/`. Back up that directory with the database. A database-only backup cannot restore issued invoices.

Create and verify one recovery bundle containing a consistent database backup and the complete invoice tree:

```bash
uv run quart backup create --output backups/ziglag-$(date +%Y%m%d).tar.gz
uv run quart backup verify backups/ziglag-$(date +%Y%m%d).tar.gz
```

Test restoration into an empty staging installation with `uv run quart backup restore ARCHIVE`. Restore refuses non-empty SQLite targets unless `--force` is supplied; PostgreSQL restores always require `--force` because `pg_restore --clean` overwrites the target database. PostgreSQL requires compatible `pg_dump` and `pg_restore` executables. Back up `.env` separately as a secret.

A bundle on the application server is not an offsite backup. Copy it to independent storage, monitor transfers, and test restoration periodically.

## Updates

Pull a reviewed release commit, synchronize locked dependencies, apply migrations, and restart the service:

```bash
cd /home/<app-user>/invoices.example.com
sudo -u <app-user> git pull --ff-only
sudo -u <app-user> uv sync --extra full --frozen
sudo -u <app-user> uv run quart db upgrade
sudo systemctl restart invoices.example.com.service
```

Confirm the installation after each update:

```bash
sudo -u <app-user> uv run quart verify --json
sudo systemctl status invoices.example.com.service
curl -fsS https://invoices.example.com/health
```

## Docker

For a container deployment:

```bash
docker compose up --build -d
```

Persist the PostgreSQL, Redis, and application instance volumes. The runtime image installs the Unicode font used for invoice PDFs.

## Before Issuing Production Invoices

- Apply all migrations and confirm one Alembic head.
- Create a domestic German VAT invoice and a reverse-charge test invoice.
- Confirm both PDFs remain one page for the normal one-line-item case.
- Download an issued PDF twice and verify the bytes remain unchanged.
- Cancel a test invoice and confirm it cannot be edited, deleted, paid, or sent.
- Have the business's Steuerberater approve the invoice wording and tax configuration.
